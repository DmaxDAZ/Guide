01

เว็บทำงานอย่างไร

ก่อนเขียนโค้ดบรรทัดแรก ควรเข้าใจว่าเมื่อพิมพ์ชื่อเว็บไซต์แล้วกด Enter เกิดอะไรขึ้นบ้าง เพราะแนวคิดเหล่านี้เป็นรากฐานของทุกเรื่องที่ตามมา

Client–Server Model

เว็บทำงานบนสถาปัตยกรรมแบบ ไคลเอนต์–เซิร์ฟเวอร์ (Client–Server) โดยเบราว์เซอร์ (Client) เป็นฝ่ายส่งคำขอ (Request) ไปยังเครื่องเซิร์ฟเวอร์ที่เก็บไฟล์เว็บไซต์ไว้ แล้วเซิร์ฟเวอร์จะประมวลผลและส่งคำตอบ (Response) กลับมา วงจรนี้เรียกว่า HTTP Request–Response Cycle และเป็นกลไกพื้นฐานที่สุดของเวิลด์ไวด์เว็บ

DNS และ URL

ชื่อโดเมน เช่น example.com ที่มนุษย์จำง่าย จะถูกระบบ DNS (Domain Name System) แปลงเป็นหมายเลข IP ที่คอมพิวเตอร์ใช้สื่อสารกันจริง ๆ ส่วน URL (Uniform Resource Locator) คือที่อยู่เต็มรูปแบบของทรัพยากรบนเว็บ ประกอบด้วยโพรโทคอล โดเมน เส้นทาง (path) และพารามิเตอร์

https://www.example.com/blog/web-basics?lang=th
└─┬──┘   └──────┬──────┘└──────┬───────┘└───┬───┘
โพรโทคอล      โดเมน           เส้นทาง        query string

HTTP / HTTPS

HTTP (HyperText Transfer Protocol) คือชุดกฎที่กำหนดรูปแบบการส่งคำขอและคำตอบระหว่างไคลเอนต์กับเซิร์ฟเวอร์ ส่วน HTTPS คือ HTTP ที่เข้ารหัสข้อมูลด้วย TLS/SSL ทำให้ข้อมูลระหว่างทางถูกดักอ่านได้ยากขึ้น ปัจจุบันเว็บไซต์แทบทุกแห่งควรใช้ HTTPS เป็นค่าเริ่มต้น

HTTP Methods ที่ใช้บ่อย

GET ขอข้อมูล · POST ส่งข้อมูลใหม่ · PUT/PATCH แก้ไขข้อมูล · DELETE ลบข้อมูล

Status Code ที่พบบ่อย

200 สำเร็จ · 301 ย้ายถาวร · 404 ไม่พบหน้า · 500 เซิร์ฟเวอร์ผิดพลาด

Browser Rendering Pipeline

เมื่อเบราว์เซอร์ได้รับไฟล์ HTML จะนำไปสร้าง DOM (Document Object Model) จากนั้นอ่านไฟล์ CSS เพื่อสร้าง CSSOM รวมทั้งสองเข้าด้วยกันเป็น Render Tree คำนวณตำแหน่งและขนาด (Layout) แล้วจึงวาดผลลัพธ์ลงหน้าจอ (Paint) — เข้าใจลำดับนี้จะช่วยอธิบายได้ว่าทำไมการวาง <script> ผิดตำแหน่งถึงทำให้เว็บโหลดช้า

สรุปสั้นDomain → DNS แปลงเป็น IP → เบราว์เซอร์ส่ง HTTP Request → เซิร์ฟเวอร์ตอบกลับไฟล์ HTML/CSS/JS → เบราว์เซอร์แปลงเป็นหน้าเว็บที่มองเห็นได้
02

HTML — โครงสร้างเนื้อหา

HTML (HyperText Markup Language) ไม่ใช่ภาษาโปรแกรมมิ่ง แต่เป็นภาษา มาร์กอัป ที่ใช้กำหนดโครงสร้างและความหมายของเนื้อหาบนหน้าเว็บ

โครงสร้างเอกสารพื้นฐาน

<!DOCTYPE html>
<html lang="th">
  <head>
    <meta charset="UTF-8">
    <title>ชื่อหน้าเว็บ</title>
  </head>
  <body>
    <h1>หัวข้อหลัก</h1>
    <p>ย่อหน้าเนื้อหา</p>
  </body>
</html>

<!DOCTYPE html> บอกเบราว์เซอร์ว่าเอกสารนี้ใช้มาตรฐาน HTML5 ส่วน <head> เก็บข้อมูลที่ไม่แสดงผลโดยตรง เช่น ชื่อหน้า การเชื่อมไฟล์ CSS และ meta tag ต่าง ๆ ขณะที่ <body> คือเนื้อหาทั้งหมดที่ผู้ใช้มองเห็น

Element, Tag และ Attribute

ทุก element ประกอบด้วย tag เปิด เนื้อหา และ tag ปิด เช่น <a href="#">ลิงก์</a> โดย href คือ attribute ที่ให้ข้อมูลเพิ่มเติมแก่ element นั้น element บางตัวไม่มีเนื้อหาและไม่ต้องปิด เรียกว่า void element เช่น <img>, <br>, <input>

Semantic HTML — ทำไมสำคัญ

แทนที่จะใช้ <div> ทุกจุด HTML5 มี element ที่สื่อความหมายในตัวเอง ช่วยทั้งด้าน SEO และการเข้าถึง (Accessibility) เพราะโปรแกรมอ่านหน้าจอและเสิร์ชเอนจินเข้าใจโครงสร้างได้ดีกว่า

Elementความหมาย
<header>ส่วนหัวของหน้าหรือ section
<nav>กลุ่มลิงก์นำทาง
<main>เนื้อหาหลักของหน้า (มีได้หน้าละ 1 ครั้ง)
<article>เนื้อหาที่แยกเป็นอิสระได้ เช่น บทความ, โพสต์
<section>กลุ่มเนื้อหาที่เกี่ยวข้องกันภายใต้หัวข้อหนึ่ง
<footer>ส่วนท้ายของหน้าหรือ section

รายการ Element ที่ใช้บ่อยที่สุด

  • ข้อความ: h1–h6, p, span, strong, em
  • ลิสต์: ul/ol คู่กับ li
  • สื่อ: img, video, audio
  • ลิงก์และตาราง: a, table/tr/td
  • ฟอร์ม: form, input, label, select, button

ฟอร์มเบื้องต้น

<form action="/submit" method="post">
  <label for="email">อีเมล</label>
  <input type="email" id="email" name="email" required>
  <button type="submit">ส่งข้อมูล</button>
</form>

การผูก label กับ input ผ่าน for/id ไม่ใช่แค่ความสวยงาม แต่ช่วยให้ผู้ใช้โปรแกรมอ่านหน้าจอทราบว่ากล่องกรอกข้อมูลนี้คืออะไร

ข้อผิดพลาดที่พบบ่อยใช้ <div> และ <span> แทนทุก element โดยไม่คำนึงถึงความหมาย ทำให้โครงสร้างอ่านยากและกระทบ SEO/Accessibility ในระยะยาว
03

CSS — การจัดรูปแบบ

CSS (Cascading Style Sheets) ควบคุมว่าเนื้อหาที่ HTML สร้างขึ้นจะแสดงผลอย่างไร ทั้งสี ระยะห่าง ตำแหน่ง และการตอบสนองต่อขนาดหน้าจอ

วิธีเชื่อม CSS เข้ากับ HTML

<!-- แนะนำ: ไฟล์ภายนอก แยกจาก HTML -->
<link rel="stylesheet" href="style.css">

<!-- ใช้ในหน้าเดียว -->
<style> p { color: navy; } </style>

<!-- inline: หลีกเลี่ยงถ้าเป็นไปได้ -->
<p style="color:navy">ข้อความ</p>

Selector พื้นฐาน

p { }            /* เลือกทุก <p> */
.card { }        /* เลือกทุก element ที่มี class="card" */
#nav { }         /* เลือก element ที่มี id="nav" */
a:hover { }      /* สถานะเมื่อเมาส์ชี้ */
.card > p { }    /* p ที่เป็นลูกโดยตรงของ .card */
h2 + p { }       /* p ที่อยู่ถัดจาก h2 ทันที */

Box Model — หัวใจของ Layout

ทุก element บนหน้าเว็บถูกมองเป็นกล่องสี่เหลี่ยม ประกอบด้วย 4 ชั้นจากในสู่นอก: content → padding → border → margin การตั้งค่า box-sizing: border-box; ให้ padding และ border นับรวมอยู่ในความกว้างที่กำหนดไว้ ช่วยคำนวณขนาดได้ง่ายขึ้นมาก จนกลายเป็นค่ามาตรฐานที่โปรเจกต์ส่วนใหญ่ตั้งไว้ตั้งแต่ต้น

* { box-sizing: border-box; }

.box {
  width: 300px;
  padding: 20px;
  border: 2px solid #333;
  margin: 16px;
}

Flexbox — จัดเรียงแบบ 1 มิติ

.container {
  display: flex;
  justify-content: space-between; /* แนวหลัก */
  align-items: center;            /* แนวขวาง */
  gap: 1rem;
}

Flexbox เหมาะกับการจัดแถวเมนู การ์ดเรียงกัน หรือจัดกึ่งกลางแนวตั้ง/แนวนอนที่ทำได้ยากด้วยวิธีเก่า

CSS Grid — จัดเรียงแบบ 2 มิติ

.gallery {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 1rem;
}

Grid เหมาะกับโครงหน้าเว็บทั้งหน้า เช่น sidebar + content หรือ gallery ที่ต้องควบคุมทั้งแถวและคอลัมน์พร้อมกัน

หน่วยวัดที่ควรรู้

หน่วยใช้เมื่อไร
pxขนาดคงที่ ไม่ยืดหยุ่นตามบริบท
%สัดส่วนเทียบกับ parent element
emเทียบกับขนาดฟอนต์ของ element นั้นเอง
remเทียบกับขนาดฟอนต์ของ html — นิยมใช้เพื่อความสม่ำเสมอ
vw / vhสัดส่วนของความกว้าง/สูงหน้าจอ
Specificity ควรรู้เมื่อกฎ CSS ขัดกัน เบราว์เซอร์เลือกใช้กฎที่ "จำเพาะเจาะจง" ที่สุด เรียงจากน้อยไปมากคือ element selector → class → id → inline style ส่วน !important จะแทนที่ทุกอย่าง จึงควรใช้ให้น้อยที่สุด
04

JavaScript — พฤติกรรมและการโต้ตอบ

ถ้า HTML คือโครงกระดูกและ CSS คือรูปลักษณ์ JavaScript ก็คือระบบประสาทที่ทำให้หน้าเว็บตอบสนองต่อผู้ใช้ได้

การเชื่อม JavaScript เข้ากับหน้าเว็บ

<!-- แนะนำ: วางก่อนปิด </body> หรือใส่ defer -->
<script src="app.js" defer></script>

แอตทริบิวต์ defer บอกให้เบราว์เซอร์โหลดไฟล์ไปพร้อมกับ HTML แต่รันสคริปต์หลังจากสร้าง DOM เสร็จแล้ว ช่วยไม่ให้หน้าเว็บค้างระหว่างโหลด

ตัวแปรและชนิดข้อมูลพื้นฐาน

let count = 0;              // เปลี่ยนค่าได้
const name = "เว็บของฉัน";   // ห้ามเปลี่ยนค่าใหม่

const isReady = true;       // boolean
const price = 129.5;        // number
const tags = ["html","css"];// array
const user = { name, age: 25 }; // object

ฟังก์ชันและ Arrow Function

function add(a, b) {
  return a + b;
}

const multiply = (a, b) => a * b;

DOM Manipulation

DOM (Document Object Model) คือโครงสร้างข้อมูลของหน้า HTML ที่ JavaScript สามารถเข้าถึงและเปลี่ยนแปลงได้แบบ real-time

const button = document.querySelector("#submit");
const message = document.querySelector(".message");

button.addEventListener("click", () => {
  message.textContent = "ส่งข้อมูลเรียบร้อยแล้ว";
  message.classList.add("success");
});

การจัดการงานแบบ Asynchronous

เมื่อเว็บต้องขอข้อมูลจากเซิร์ฟเวอร์โดยไม่ให้หน้าเว็บค้าง จะใช้รูปแบบ asynchronous ผ่าน fetch ร่วมกับ async/await

async function loadPosts() {
  const response = await fetch("/api/posts");
  const posts = await response.json();
  console.log(posts);
}

แนวคิดสำคัญที่ควรเรียนต่อ

  • Event Loop — กลไกที่ทำให้ JavaScript ทำงานแบบ single-threaded แต่จัดการงานพร้อมกันได้
  • Closures & Scope — ขอบเขตการมองเห็นของตัวแปร
  • ES Modules (import/export) — แบ่งโค้ดเป็นไฟล์ย่อยที่จัดการง่าย
ระวังโค้ด JavaScript ที่รันในเบราว์เซอร์ผู้ใช้ทุกคนมองเห็นได้ ห้ามฝัง API key หรือข้อมูลลับไว้ในสคริปต์ฝั่ง client เด็ดขาด
05

Responsive & Mobile-first Design

ผู้ใช้เข้าเว็บจากหน้าจอหลากหลายขนาด ตั้งแต่มือถือจนถึงจอมอนิเตอร์ใหญ่ เว็บที่ดีต้องปรับตัวได้กับทุกขนาด

Meta Viewport — จุดเริ่มต้นที่มักถูกลืม

<meta name="viewport" content="width=device-width, initial-scale=1.0">

หากไม่มีบรรทัดนี้ มือถือจะแสดงหน้าเว็บโดยย่อทั้งหน้าให้พอดีจอ ทำให้ตัวอักษรเล็กจนอ่านไม่ออก

Media Query

.container { padding: 1rem; }

@media (min-width: 768px) {
  .container { padding: 2rem; }
}

@media (min-width: 1200px) {
  .container { padding: 3rem; max-width: 1100px; margin: 0 auto; }
}

แนวทาง Mobile-first คือเขียน CSS สำหรับหน้าจอเล็กสุดก่อน แล้วค่อยเพิ่มกฎสำหรับหน้าจอที่ใหญ่ขึ้นด้วย min-width ทำให้เว็บเบาและควบคุมง่ายกว่าการเขียนกลับด้าน

รูปภาพที่ตอบสนองต่อขนาดจอ

img { max-width: 100%; height: auto; display: block; }
Breakpoint ที่นิยมใช้อ้างอิงมือถือ < 600px · แท็บเล็ต 600–1024px · เดสก์ท็อป > 1024px — ตัวเลขจริงควรปรับตามเนื้อหา ไม่ใช่ยึดตายตัว
06

เครื่องมือของนักพัฒนา

การเขียนเว็บในปัจจุบันอาศัยเครื่องมือรอบตัวหลายอย่างที่ช่วยให้ทำงานเร็วและตรวจจับข้อผิดพลาดได้ไว

Code Editor

เช่น Visual Studio Code — มี extension ช่วยไฮไลต์ไวยากรณ์ เติมโค้ดอัตโนมัติ และเชื่อมกับ Git ในตัว

Browser DevTools

กด F12 เพื่อดู DOM ที่เรนเดอร์จริง ตรวจ Console หา error และดู Network tab เพื่อวิเคราะห์ความเร็วโหลด

Git & GitHub

ระบบควบคุมเวอร์ชันที่บันทึกประวัติการแก้โค้ด ทำงานร่วมกับผู้อื่นได้โดยไม่ทับไฟล์กัน

Package Manager

เช่น npm หรือ pnpm ใช้ติดตั้งและจัดการไลบรารีของ JavaScript ที่โปรเจกต์ต้องพึ่งพา

คำสั่ง Git ที่ใช้บ่อยที่สุด

git init                     # เริ่มโปรเจกต์ git ใหม่
git add .                    # เตรียมไฟล์ที่แก้ไขทั้งหมด
git commit -m "เพิ่มหน้าแรก"   # บันทึกการเปลี่ยนแปลง
git push origin main         # ส่งขึ้น GitHub

การ Deploy เว็บไซต์ให้ใช้งานจริง

เมื่อเขียนเว็บเสร็จในเครื่องตัวเอง ขั้นตอนสุดท้ายคือนำขึ้นสู่อินเทอร์เน็ตให้คนอื่นเข้าถึงได้

องค์ประกอบที่ต้องมี

  • Domain name — ชื่อที่จดทะเบียนไว้ เช่น ผ่านผู้ให้บริการจดโดเมน
  • Hosting/Server — เครื่องที่เก็บไฟล์เว็บไซต์และตอบ HTTP request
  • DNS records — เชื่อมโดเมนเข้ากับ IP ของ hosting
  • SSL Certificate — เปิดใช้ HTTPS (ผู้ให้บริการยุคใหม่ส่วนมากทำให้ฟรีและอัตโนมัติ)

ทางเลือกยอดนิยมสำหรับผู้เริ่มต้น

เว็บไซต์แบบ Static

GitHub Pages, Netlify, Vercel — เหมาะกับ HTML/CSS/JS ล้วน หรือเว็บที่ build ด้วย React/Vue มีระดับฟรีให้ใช้งาน

เว็บไซต์ที่มี Back-end

Render, Railway หรือ VPS (เช่น DigitalOcean) — เหมาะกับเว็บที่ต้องรันเซิร์ฟเวอร์และเชื่อมฐานข้อมูล

Accessibility และ SEO เบื้องต้น

เว็บที่ดีต้องเข้าถึงได้สำหรับทุกคน และค้นเจอได้ง่ายบนเสิร์ชเอนจิน สองเรื่องนี้เชื่อมโยงกับพื้นฐานที่กล่าวมาทั้งหมดโดยตรง

หลักการ Accessibility (a11y) เบื้องต้น

  • ใช้ semantic HTML แทนการยัด div ทุกอย่าง
  • ใส่ alt ให้รูปภาพเสมอ เพื่อให้โปรแกรมอ่านหน้าจอบรรยายภาพได้
  • ตรวจสอบว่าใช้เมาส์ไม่ได้ก็ยังกด Tab ไปยังทุกปุ่ม/ลิงก์ได้ครบ
  • เลือกคู่สีตัวอักษร/พื้นหลังที่มีความต่างของความสว่างเพียงพอ (contrast)

พื้นฐาน SEO ที่ควบคุมได้จากโค้ด

<title>ชื่อหน้าที่สื่อความหมายชัดเจน</title>
<meta name="description" content="สรุปเนื้อหาของหน้านี้สั้น ๆ">
<h1>มีหัวข้อหลักเพียงหนึ่งเดียวต่อหน้า</h1>

เสิร์ชเอนจินให้ความสำคัญกับโครงสร้างที่ชัดเจน ความเร็วในการโหลด และการรองรับมือถือ — ซึ่งล้วนเป็นผลพลอยได้จากการเขียน HTML/CSS ที่ถูกต้องตามหัวข้อก่อนหน้าทั้งหมด

เชื่อมโยงกันSemantic HTML (หัวข้อ 2) + Responsive Design (หัวข้อ 5) + ความเร็วในการโหลด คือสามเสาหลักที่ทั้ง Accessibility และ SEO ต้องการร่วมกัน

แหล่งเรียนรู้และอ้างอิงที่เชื่อถือได้

เนื้อหาในคู่มือนี้สรุปจากแนวคิดพื้นฐานที่ได้รับการยอมรับในอุตสาหกรรม แนะนำให้ศึกษาเพิ่มเติมจากแหล่งต้นทางต่อไปนี้โดยตรง เพื่อความถูกต้องและทันสมัยที่สุด
